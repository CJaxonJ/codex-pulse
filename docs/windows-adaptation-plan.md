## 1. 先完成托管任务停机保护

停机保护已接入 Windows watcher 与安装／卸载源码，`393e7bc` 的真实 Windows 门禁已通过。`RuntimeMaintenanceGuard` 提供进程归属互斥及严格任务记录检查。仅未启动的排队任务、字段完整的已完成任务通过本地准入；活跃、启动中、额度暂停、等待审批、损坏和未知记录均拒绝。不会为了安装主动打断任务。互斥与记录检查不是远端执行结束的独立证明。

本机验证：完整回归 331 通过、47 个 Windows 专属跳过、0 失败。新增覆盖事务在停机前拒绝活跃任务、维护跨激活／回滚持续持有、未完成 journal 阻止新操作、旧协议和错误运行目录拒绝、退出前等待锁归属发布及状态读取争用。真实 Windows 结果不沿用上一提交的通过结果。

当前接线方式：Windows 任务／恢复／自动用卡的轮询操作共用维护锁；额度读取先执行，安装健康检查不需要放行用户任务。安装和卸载在写事务记录、改自启或停机前申请维护保留，直到激活验证／回滚完成才释放。正在运行的后台必须报告协议版本与匹配的运行目录，且安装文件本身支持该协议；旧开发版无法证明参与时拒绝接管。若维护进程死亡，未完成的安装／卸载 journal 继续阻止模型任务；后续清理修复前不自动放行。macOS 未启用这条新 Windows 门禁。

本段必须在 Windows 验证，不能只看本机单测：

执行检查点（2026-10-31）：接线代码 `393e7bc4383a24960848dd7ef3a0d421e24dede5` 的 [Windows 验收 41174715208](https://github.com/CJaxonJ/codex-pulse/actions/runs/41174715208) 和 [跨平台门禁 41174715188](https://github.com/CJaxonJ/codex-pulse/actions/runs/41174715188) 均成功。Windows Node 22 关键组合 129 通过、1 跳过，全量 352 通过、3 跳过；Node 20 任务成功。实际 ZIP 入口确认 `maintenanceBlocksQueuedActivation: true`，无模型启动尝试。尚不发布：继续中断恢复、双击安装入口和真实桌面／睡眠验收。

- 任务启动／恢复与维护共用同一互斥边界，防止“检查时空闲，停机前又启动”。涉及自动用卡时也不能在维护中途启动敏感操作。
- 安装、升级、卸载先申请维护准入，再修改自启或请求停机；维护期间新后台允许刷新额度做健康检查，但不能开始用户任务。保护持续到提交完成或回滚结束。
- 明确运行中旧版本是否参与该协议，核实宿主归属／版本；无法证明的旧开发版不能猜测安全或悄悄接管。
- 额度暂停不是终态。第一版保守拒绝，之后若要允许，须核实实际轮次已结束，不能仅据中断请求已返回放行。
- 测试覆盖正在启动、正在运行、等待审批、未知状态、原进程退出、并发维护和激活失败回滚。拒绝时必须零停机、零目录切换、保留任务与配置；维护中不能有新模型任务启动。

协议依据：[官方 App Server 文档](https://learn.chatgpt.com/docs/app-server) 的 `turn/completed` 与 `thread/turns/list`。先核对当前实际 CLI 协议，不用旧接口猜测运行状态。

## 2. 补安装中断恢复

处理安装／卸载中断和 committed journal 的清理重试。只根据已核实的阶段、目录指纹和进程状态恢复；新增用户文件、备份变化、未知活跃进程时保留现场。支持重复操作，不覆盖未知目录，不全目录删除历史。

本轮源码已加入版本化恢复记录：停机前持久保存原标记／上下文及插件归属，激活前由原生只读接口预览即将写入的上下文。重开安装或卸载入口时，在同一安装锁和任务门禁内恢复：未提交安装回滚、已提交安装清理、部分卸载继续完成；没有足够快照的旧中断记录保持拒绝。区分同内容重装、移动／删除已执行但回执丢失、恢复再次中断，不拿更新时间猜测。用户修改运行文件、备份或上下文后拒绝覆盖。macOS 本轮完整回归 342 通过、47 跳过。真实 Windows 门禁将验证实际终止安装进程后，从正常入口恢复，以及移除真实自启后中断卸载再重试；这些新证据尚待验收。

后续实测：`ce203f1` 暴露 WinExe 默认 stdout 编码破坏中文预览路径，`17a3fc2` 改为显式 UTF-8，保留原中文路径断言。[验收 41177878054](https://github.com/CJaxonJ/codex-pulse/actions/runs/41177878054) 的原生关键组与真实 ZIP E2E 已通过：`killedInstallerRecoveredByNextEntry: true`、`interruptedUninstallResumed: true`，模型／用卡为 0。Node 20 整轮成功；Node 22 串行全量仍有一次后续正常升级失败，不能宣称整轮已通过。正在补更完整的阶段／原因诊断，以及调度器旧实例释放的停机后置条件；后者是源码中存在的缺口，尚不能据现有日志断言它是该次失败根因。保持 IgnoreNew 防并发策略，不能为启动成功改成并行。新接口只从源包组件查询已安装目录的已核实自启状态，不要求旧运行时支持新字段。

## 3. 补普通用户入口

原生双击安装窗口、明确的进行中／成功／失败状态、安装后快捷入口和卸载入口。捆绑 Node，不要求用户理解终端；Hook 审查和用卡授权由用户分别亲自确认。使用现有图标和界面风格，不增加仪表盘或新账号系统。补一页最短安装说明。

窗口源码已接入：完整解压包双击 `CodexPulse.exe` 默认进入安装，已安装的程序默认进入设置；安装、重试、卸载确认在同一窗口，后台子进程未退出时禁止重复点击和关闭。主流程复用已有事务入口，无终端、Shell、管理员提升或自动授信。完成后创建精确归属的用户快捷方式，外部／用户修改的入口保留；自定义数据配置不覆盖默认用户的开始菜单。普通用户卸载入口是原解压包的原生管理窗口，不使用脆弱的自删命令。使用步骤见 [Windows 简明说明](windows-quickstart.md)。尚待新提交的真实 UI／ZIP 验收；本机 342 项通过，Windows UI 为专属跳过。

`f0016f6` 的 [Windows 验收 41179679318](https://github.com/CJaxonJ/codex-pulse/actions/runs/41179679318) 已读取最终日志。两组原生关键组合通过，后续正常升级用例这轮通过；全量均仅失败在新增快捷方式用例：WScript 动态 COM 调用返回 ArgumentException `0x80070057`。实际 ZIP 入口经原生安装窗口完成安装，但没有生成快捷方式，因此在真实文件断言失败，尚未走到该 fixture 的窗口卸载。窗口按钮对齐、后台子进程未结束时禁止重复操作／关闭、失败可重试及已安装默认进设置均通过；已人工检查这轮实际截图，未公开宣传。下一修正切换为显式 Unicode `IShellLinkW`，保持归属核实和未知入口拒绝；新增中断卸载后标记已删仍可进入卸载确认。另对照 Microsoft TASK_STATE 文档纠正 Ready=3／Queued=2，原生后置条件与排队拒绝断言一起修正，不能只让测试跟着错误值通过。最新本机完整回归 346 通过、51 个 Windows 跳过。下一步跟进新提交的真实 Windows 最终结果。
