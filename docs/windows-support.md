# Windows 适配验收记录

状态：开发中，**尚未支持对外安装，不是已发布的 Windows 版**。目标是原生 Windows 上的完整额度监控、通知、用户本人保护授权、暂停与恢复、安装升级及卸载，不以 WSL 或只跑 CLI 代替。

## 必须完成的验收

- [x] Windows 原生运行层：Codex exe/npm 启动、中文／空格路径、本地数据目录、进程退出错误。
- [x] Hook Windows 命令及协议：实际 PowerShell／cmd 执行；官方 CLI 隔离配置及真实授权界面中取消不写信任、确认后信任和跨进程读取；脚本变化会拒绝旧审查。
- [x] 提醒与简洁设置界面：等级、常驻提醒、原帖回看、续跑计划、偏好及单独用卡授权（见真实 Windows 验收记录；系统勿扰和物理桌面显示仍有独立边界）。
- [x] 用户级后台与自启注册：实际系统任务拉起、单实例、异常连接重启、禁用／停止／移除；当前用户 InteractiveToken、RunLevel 0，不请求系统密码或提权。
- [ ] 实机恢复：物理退出／重新登录、锁屏／睡眠／重启、断网恢复及真实 Desktop／模型任务执行。

- [ ] 恢复安全：后台重启、并发、重复事件、正在运行／状态未知、审批、取消、工作区变更。
- [x] 当前代码的 macOS 完整回归，不改用户本机现有安装和信任；后续改动继续执行门禁。

## 官方依据

- [Hooks](https://learn.chatgpt.com/docs/hooks)：Windows 有独立 `commandWindows`；插件提供 `PLUGIN_ROOT`，安装不等于信任。
- [App Server](https://learn.chatgpt.com/docs/app-server)：stdio JSONL 初始化、请求与响应保持原协议；不能因为程序能连接就声称真实任务已续跑。

首次检查：原有后台、通知、数据目录和插件安装器均为 macOS 专用。当前先抽出跨平台路径／进程调用；后续按以上完整范围继续，不缩减成“Node 单测通过即支持 Windows”。

## 私有目录接线与真实 Windows 验收

Windows watcher 启动前新增真实 DACL 检查：只允许当前 Windows 用户和 SYSTEM，覆盖已有文件并让新文件继承；设置失败则不启动后台，不把 chmod 当成 Windows 权限保障。它不改变所有者、SACL 或系统策略，也不会请求提升权限。

权限修改前先验证目录边界和完整现有树：拒绝磁盘／个人资料／系统／Temp 等大目录及其祖先、UNC、备用数据流和 reparse point（包括失效 junction）；限制扫描规模。已有检查点内容不改，不跟随链接去处理树外路径。

新增 Windows 真机测试会先给隔离文件加入 Everyone 访问，再验证移除、已有内容不变、新文件继承、重复调用、junction／失效 junction／过宽目录拒绝且原权限不变。这些是本机 ACL 行为验证，不是已完成安装器验收，也不代表能抵御管理员或同一用户下的恶意程序。Windows runner 结果未读回前不勾选完成。

## 后台进程归属基础（开发中，尚待 Windows 验收）

先为 App Server 连接增加原生进程边界，不把整个 watcher 放进“退出时全杀”的 Job：

- 每次连接通过捆绑原生程序创建独立 Job；子进程以 suspended 状态创建，确认加入 Job 后才恢复，避免启动速度快时先生成逃逸子进程。
- JSONL 输入／输出仍经管道转发，无 shell 拼接；stdin 断开或桥接进程被杀时，只清理本连接的进程树。用户已有 Desktop／CLI、watcher 自己、独立提醒窗口都不属于该 Job。
- 初始化超时会停止本连接，而不是留下无主进程；旧连接退出事件不得覆盖新连接的状态。显式 stop 立即结束待处理请求。
- 新增真实 Windows 进程测试：EOF、强杀桥接程序、强杀实际 Node owner、初始化超时；先确认真实子进程和孙进程存活，再验证清理。另保留无关进程及 owner 发出的真实常驻提醒，并操作真实按钮关闭，不能只看 PID 文件或模拟 cleanup 返回值。

这些测试不使用真实账户或模型；编译与 Windows 结果读回前不宣布进程清理通过。用户级后台、自启和安装事务尚未因此完成。

首轮 `0876b25` 已成功编译，并在两组 Windows 中通过四项新进程归属测试；Node 22 的关键组合运行却有一项已有 Hook 进程用例返回 code=5、stderr 空，而串行全量中通过。因此整轮不能算通过。已增加该隔离 Hook 的 signal／stdout 失败诊断；另外审查发现测试清理不该按历史 PID 强杀（PID 可能被其他并行测试复用），改为使用原 ChildProcess／Job 句柄，只按 UUID 核对并关闭本测试的提醒。未证明这就是 code=5 的原因，不直接覆盖失败记录。

Windows watcher 另加独立的进程归属记录：长驻计时器完成初始化时不能释放；仅 --once 完成或启动失败时主动释放，异常死亡后由后续进程核对 OS liveness 再回收。新增真实 CLI 验收会启动一个持续监控，确认另一个 --once 被拒绝且原进程仍在；强杀原进程后才允许替换，再确认 --once 能正确释放。不会把时间流逝当成进程已停止。该新单实例测试尚待 Windows 回读。

## 原生后台宿主（隔离 Windows 进程验收已通过，自启及安装待实现）

新增 `--background` 托盘进程，隐藏控制台，仅启动捆绑 Node 的 watch；用内核文件锁限制同一数据目录一个宿主，用原有进程归属记录限制一个实际 watcher。异常连接退出引起 watcher 退出后，后台按有上限的退避重试；发现另一个 watcher 时不假报已接管。

托盘提供设置、历史、计划和退出；停止通过当前 generation 的用户级事件，不按状态文件里的 PID 杀进程。退出前核对 watcher 也已停止，不能仅因托盘进程消失就允许安装器替换文件。状态只记录进程状态，不把“已启动进程”当作账户、通知或真实任务就绪。

## 安装切换的互斥基础（待 Windows 验收，不是已实现安装器）

新增当前数据目录的内核维护锁：原生后台在拿到自己的 guard 前检查；直接 CLI 在 ACL 准备及获取 watcher 归属记录期间持有同一锁。安装 helper 持锁后仍核对后台 guard 及真实 watcher 已停止，而不信任旧状态文件；只读 probe 不启动监控，不因锁重入导致死锁。这样不能在“先检查、后替换”的间隙又拉起后台。

运行目录的移动由持有锁的原生进程执行，不由收到一次 ready 的 Node 父进程继续改文件；helper 被杀后，Node 不能绕过已经消失的锁继续移动。只允许 app 及带随机标识的 install／backup／failed 子目录，不提供任意路径、删除或 shell 命令。EOF／进程死亡释放 OS 锁；不按历史 PID 杀进程。在已安装 app 内运行的 helper 拒绝替换自己的可执行文件，Node owner 位于待替换 runtime 时也拒绝。

新增真实 Windows 进程用例：维护期间拒绝托盘、直接 CLI 和第二个安装者；实际移动旧／新目录再恢复旧目录；活托盘或独立 watcher 阻止维护但不被杀；强杀真实 helper 后不能移动、后续能重新获取锁；绕过 JS 校验直接向原生端发送目录穿越仍不能移动隔离的外部目录；拒绝从已安装运行时执行自替换。全部使用隔离文件和 Codex RPC 对端，不调用模型或用卡。

这只是安装事务所需的系统边界，尚未包含安装编排、插件／配置回滚、依赖包、卸载或 GUI 引导，不据此勾选安装交付。
