## 后台进程归属基础（开发中，尚待 Windows 验收）

## 安装切换的互斥基础（待 Windows 验收，不是已实现安装器）

新增当前数据目录的内核维护锁：原生后台在拿到自己的 guard 前检查；直接 CLI 在 ACL 准备及获取 watcher 归属记录期间持有同一锁。安装 helper 持锁后仍核对后台 guard 及真实 watcher 已停止，而不信任旧状态文件；只读 probe 不启动监控，不因锁重入导致死锁。这样不能在“先检查、后替换”的间隙又拉起后台。

运行目录的移动由持有锁的原生进程执行，不由收到一次 ready 的 Node 父进程继续改文件；helper 被杀后，Node 不能绕过已经消失的锁继续移动。只允许 app 及带随机标识的 install／backup／failed 子目录，不提供任意路径、删除或 shell 命令。EOF／进程死亡释放 OS 锁；不按历史 PID 杀进程。在已安装 app 内运行的 helper 拒绝替换自己的可执行文件，Node owner 位于待替换 runtime 时也拒绝。

新增真实 Windows 进程用例：维护期间拒绝托盘、直接 CLI 和第二个安装者；实际移动旧／新目录再恢复旧目录；活托盘或独立 watcher 阻止维护但不被杀；强杀真实 helper 后不能移动、后续能重新获取锁；绕过 JS 校验直接向原生端发送目录穿越仍不能移动隔离的外部目录；拒绝从已安装运行时执行自替换。全部使用隔离文件和 Codex RPC 对端，不调用模型或用卡。

这只是安装事务所需的系统边界，尚未包含安装编排、插件／配置回滚、依赖包、卸载或 GUI 引导，不据此勾选安装交付。
