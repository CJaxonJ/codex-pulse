# Windows 适配验收记录

状态：开发中，**尚未支持对外安装，不是已发布的 Windows 版**。目标是原生 Windows 上的完整额度监控、通知、用户本人保护授权、暂停与恢复、安装升级及卸载，不以 WSL 或只跑 CLI 代替。

## 必须完成的验收

- [x] Windows 原生运行层：Codex exe/npm 启动、中文／空格路径、本地数据目录、进程退出错误。
- [x] Hook Windows 命令及协议：实际 PowerShell／cmd 执行；官方 CLI 隔离配置中取消不写信任、确认后信任和跨进程读取。Windows 本人授权界面的完整操作尚待验收。
- [ ] 提醒与简洁设置界面：等级、常驻提醒、原帖回看、续跑计划、偏好及单独用卡授权。
- [ ] 用户级后台：登录后启动，异常退出重启，断网／睡眠恢复，不需要管理员权限。
- [ ] 安装包：依赖处理、安装前检查、升级失败回滚、重复安装和完整卸载（默认保留历史）。
- [ ] 核心链路：真实 Windows 进程测试 10% 阻止新工具、保存原目标和计划、额度恢复后同一会话仅续跑一次。
- [ ] 恢复安全：后台重启、并发、重复事件、正在运行／状态未知、审批、取消、工作区变更。
- [x] 当前代码的 macOS 完整回归，不改用户本机现有安装和信任；后续改动继续执行门禁。
- [ ] Windows runner 执行证据；物理睡眠和桌面通知若未实测，明确保留未验收状态。

## 官方依据

- [Hooks](https://learn.chatgpt.com/docs/hooks)：Windows 有独立 `commandWindows`；插件提供 `PLUGIN_ROOT`，安装不等于信任。
- [App Server](https://learn.chatgpt.com/docs/app-server)：stdio JSONL 初始化、请求与响应保持原协议；不能因为程序能连接就声称真实任务已续跑。

首次检查：原有后台、通知、数据目录和插件安装器均为 macOS 专用。当前先抽出跨平台路径／进程调用；后续按以上完整范围继续，不缩减成“Node 单测通过即支持 Windows”。

## 已核实的证据（2026-10-29）

- [Windows Node 20／22，e30785f](https://github.com/CJaxonJ/codex-pulse/actions/runs/40817466086)：两种真实 shell 在中文／空格路径下执行 Hook，移除 PATH 中的 Node 后使用捆绑运行时；10% 拦截、保存最初 Goal 和计划、恢复时排队一次、首个工具校验工作区、重复唤醒拦截。未知／仍运行的生命周期不因额度恢复而误启动。
- 以上恢复测试使用真实 Windows 进程、文件系统和 PowerShell，但 Codex RPC 对端为隔离假服务。它**不是实际模型在 Windows Desktop 中继续任务的证明**；替换控制器也不等于服务重启验收。
- 同一 Windows 工作流使用实际 `@openai/codex@0.163.0-alpha.11.1`，只在临时 CODEX_HOME 中验证 Hooks 审查协议；不读取真实账户，不消耗模型额度。
- 实际 Windows 文件共享冲突测试覆盖写入检查点时的暂时占用；自动用卡操作账本改用 `MoveFileExW(REPLACE_EXISTING | WRITE_THROUGH)`，不忽略目录 fsync 在 Windows 上的失败，也不实际消费卡。
- [macOS 对应回归，e30785f](https://github.com/CJaxonJ/codex-pulse/actions/runs/40817466186)通过。Windows 专属测试在 macOS 明确跳过，macOS 安装器测试不冒充 Windows 安装验收。

## 正在补齐，不能据此宣传已支持

Windows 原生通知、原帖历史和续跑计划界面已实现，并在 [Windows Node 20／22，d267920](https://github.com/CJaxonJ/codex-pulse/actions/runs/40819947265) 通过实际编译与界面验收。该提交两组全量回归均为 265 项通过、1 项 macOS 专属测试跳过；另有 20 项关键进程测试单独全部通过。[对应 macOS 门禁](https://github.com/CJaxonJ/codex-pulse/actions/runs/40819947121)也通过；本机 macOS 完整回归为 279 项通过、9 项 Windows 专属测试跳过，公开内容检查未发现匹配项。

- 真正启动 GUI，读取 Unicode 正文和原帖入口，检查三个操作按钮同一基线，并点击真实按钮确认窗口进程正常退出。界面自动化在 UIA 把 WinForms 按钮归为 Pane 时，使用已核对进程和类名的原生 HWND 发送 `BM_CLICK`，不是伪造测试控件或写成功标记。测试截图留在该工作流的短期附件中；已人工查看其中一轮实际渲染。
- 保护“显示成功”的含义：只有 `IsWindowVisible` 确认后才应答；另外实测 `windowsHide=true` 的隐藏窗口必须失败，不得假报展示。普通系统气泡只记录请求已接受，系统勿扰模式仍可能隐藏它；原生通知进程在预定生命周期后正常退出。
- 消息历史及计划窗口调用真实捆绑 Node／CLI，临时路径含中文和空格；即使 Codex 二进制不存在，仍能读取已存消息与原目标、下一步计划，不访问账户或模型。来源摘要与逐字原文必须区分，旧记录缺失或异常时间不能伪造为当前时间。
- 首轮界面测试实际发现并修正了 WinExe 没有控制台却设置 Console 编码、GUI 被后台隐藏参数隐藏两处问题。保留失败记录，不以“编译成功”替代用户能看到窗口。

完整设置和单独授权、用户级后台服务、安装升级回滚／卸载、私有目录 ACL，以及实际 Windows Desktop 任务续跑、物理睡眠和桌面系统通知仍未验收。当前没有 Windows 用户安装包，也没有发布 Windows 版本。

4. 才生成 Windows 候选包与最简使用说明；实际桌面、任务执行及睡眠场景未证明的部分仍保留未验收，不能打包后宣布目标完成。

## 设置与授权窗口接线检查点

`0360c8c` 已加入设置首页、提醒开关、提前预警比例、保护策略和分别确认的 Hook／临期用卡授权。保存只提交已修改字段；关闭窗口不自动保存。授权窗口沿用原来的版本、哈希和来源校验，不绕过 Codex 的授权接口，也不重启用户正在运行的 Codex。

- 本机 macOS：279 项通过、11 项 Windows 专属测试跳过；公开内容检查通过。Windows 构建也已通过编译。
- 首轮真实 Windows 测试已通过偏好保存、保留另一进程改动、重开后读回和未保存退出；完整授权与用卡窗口验收仍未通过，不据此勾选交付完成。
- 首轮新测试发现驱动错误：不能通过窗口消息把本进程的内存地址当作另一个进程的控件数据；同步按钮调用也不能等待模态框关闭。`01f5b25` 改用无指针的原生标签切换和异步按钮消息，后续仍需观察真实 UI 与文件结果。
- 另一个重复运行发现，通知测试在 helper 主动解除进程引用后可能丢失等待退出的事件循环；测试现在显式保留其进程句柄直到真实退出，生产通知仍按原设计独立于 watcher 存活。
- 已读取 [Windows 工作流 40821580189](https://github.com/CJaxonJ/codex-pulse/actions/runs/40821580189) 的最终日志：失败。偏好保存／重开仍通过；两组用卡授权及 Node 22 保护详情均在点击后找不到模态窗口。没有宣称授权验收通过。
- 本次把测试定位从 UIA 桌面的直接子节点改为枚举测试进程的真实 HWND，再读取准确窗口；失败时保留仅属于隔离进程的窗口名称、可见性及 owner，避免盲目重跑。新增断言验证授权窗口可见、归属正确且主窗口确实被模态阻塞。是否解决原失败仍需新的 Windows 运行结果证明。

本轮只收尾这组窗口验收；后台、自启、ACL 和安装包没有开始新增实现，原完整 Windows 目标继续保持未完成。
